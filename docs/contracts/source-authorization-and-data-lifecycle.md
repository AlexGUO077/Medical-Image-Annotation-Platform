# 数据来源与保留最小契约

状态：2026-09-20 由项目临时负责人批准，限合成数据开发阶段使用。源开发手册是实现范围的权威；未来接入真实医学数据时重新评审来源授权、合法基础和保留期限。

依据：源开发手册 §4、§7.1、§8.3；[需求基线](../医学影像标注平台-需求拆解与实施基线.md) D-30、D-31、D-33。

## 当前数据边界

- 当前环境只允许合成数据，`cases.source` 固定记录为 `synthetic`。
- 按源手册实现 `cases.source` 必填和全程携带，不为合成数据阶段新增来源授权表、授权事件表或审批系统。
- 真实 DICOM、原始报告、患者信息、脱敏映射和生产备份不得进入当前开发环境、Git、PR 或日志。
- 未来接入真实数据前，再根据实际提供方协议确定来源台账和授权结构；该决定不提前扩张 WP-01 的源手册 16 表范围。

## 源手册明确的保留规则

| 对象 | 最小规则 |
| --- | --- |
| PostgreSQL 业务表 | 按源手册使用软删除字段，不另建删除编排系统 |
| 审计日志 | 只增不删，保存不少于 3 年 |
| PostgreSQL 备份 | 每日 `pg_dump`，保留最近 30 份 |
| Orthanc 与 MinIO | 每日异地 rsync，或使用 OSS 版本控制桶 |
| 帧缓存 | Redis TTL 30 分钟 |
| 导入临时文件 | 单次导入任务结束后直接清理，不作为业务数据长期保存 |
| 合成测试数据 | 可由项目负责人按测试需要手工清理 |

导出链接只实现源手册要求的 `expire_at` 和时效失效；具体时长在导出模块启动时确认，不在 WP-S0 提前增加规则。

## 真实数据重新评审条件

未来首次接入真实医学数据前，至少重新确认数据提供方、允许用途、有效期、撤回处理、正式分类分级和适用流程。未完成时继续拒绝真实数据，不影响合成数据工程开发。
