# 数据处理、来源授权与生命周期契约（WP-S0 草案）

状态：学生项目阶段由项目发起人暂时全权接管项目，并承担项目/数据、信息安全和医学影像等内部责任角色；当前仅允许合成数据。未来计划接入真实医学数据时，必须另行取得责任单位、数据提供方及适用的法务/伦理/信息安全批准，本草案不能作为真实数据准入证明。

依据：源开发手册 §1.2、§1.3、§2.6、§7.1～§7.3、§8.4；[需求基线](../医学影像标注平台-需求拆解与实施基线.md) §8.4～§8.8、WP-S0、SG-0/SG-1、D-30/D-31/D-33。

## 1. 处理清单与责任边界

| 数据/产物 | 分级 | 进入位置 | 允许用途 | 默认访问主体 | 禁止事项 |
| --- | --- | --- | --- | --- | --- |
| 原始 DICOM、原始报告、未脱敏压缩包 | S4 | 隔离导入区 | 授权核验、去标识化、人工复核 | 独立导入服务；经单独授权的少数管理员 | 普通开发测试、前端返回、日志/ES、直接下载、长期暂存 |
| `mask_map`、UID 对照 | S4 | 独立加密存储 | 经批准的纠错或追溯 | 单独授权管理员，二次验证 | 普通查询、批量浏览、返回前端、写入日志/ES |
| 去标识化影像、报告、附件、病例及标注 | S3 | Orthanc、MinIO、PostgreSQL | 已授权的标注、审核、教学展示等具体用途 | 资格、任务分派、病例状态和来源授权均满足的用户 | 目的外使用、跨病例访问、原始影像下载、未经批准导出 |
| 用户实名、联系方式、绩效、IP、详细审计 | S2 | PostgreSQL、审计存储 | 账号管理、安全审计和必要运维 | 最小职责管理员/审计员 | 公开、无关看板展示、进入普通业务日志 |
| 已批准公开且不含个人信息的说明、静态资源 | S1 | Web/CDN | 已批准公开用途 | 公开 | 未经版权和内容核验即发布 |

混合数据按最高级别处理。缓存、队列、备份、搜索索引和导出物不得降低原数据分级。当前临时角色安排只覆盖学生项目内部工程判断；责任单位尚未确认正式分级与等保适用性，因此本表不是正式定级结论。

## 2. 来源授权台账契约

`cases.source` 仅是展示字段。每个真实数据导入批次必须关联一条已生效的来源授权记录；字段缺失、文件摘要不匹配、授权未生效、已到期/撤回或用途不覆盖时，导入正式区、建任务、发布和导出均须失败关闭。

建议在 WP-01 固化以下逻辑实体；字段名可随数据库命名规范调整，但语义不得减少：

| 实体 | 必填内容 |
| --- | --- |
| `data_sources` | `id`、提供单位、责任单位、受控联系人引用、状态、创建/更新审计字段 |
| `source_authorizations` | `id`、`source_id`、授权/协议/伦理文件类型与编号、文件加密摘要、合法处理基础、起止时间、地域、人员范围、状态、批准人及批准时间 |
| `authorization_scopes` | 影像/报告/附件/术语等资产类型，以及标注、教学展示、科研分析、模型训练、对外共享、商业使用、导出、衍生标注、再许可等逐项允许/拒绝值 |
| `source_batches` | `id`、`source_id`、`authorization_id`、批次标识、导入者、接收时间、对象清单摘要、隔离/脱敏/复核/清理状态及证据引用 |
| `authorization_events` | 生效、暂停、到期、撤回、范围变更；原因、操作者、时间及前后值，只增不删 |

约束：

- 授权文件本体放受控对象存储，数据库只保存引用和加密摘要；不得提交 Git、PR、Issue 或 CI artifact。
- 用途采用明确枚举和逐项决定，不以“科研/教学”概括推定其他用途。
- 导出必须额外记录接收方、目的、字段/影像范围、双人审批链、交付方式、失效时间和接收证明。
- 授权撤回、到期或范围缩减后立即阻断新使用，并生成存量病例、衍生标注、已发布内容、备份和导出物的处置任务；处置规则由授权文件和责任单位决定。
- 台账读写、状态变更和授权判定都写审计；业务服务只能通过统一授权判定服务访问，不允许各控制器自行解释台账。

## 3. 生命周期与保留边界

| 对象 | 当前硬边界 | 精确期限/触发条件 |
| --- | --- | --- |
| 原始暂存包 | 只在隔离区完成核验、去标识化和复核；成功入库后立即进入可验证清理流程 | 待责任单位按来源协议确认最大暂存时长及失败包处置时限 |
| 去标识化影像、报告、附件、标注 | 仅在授权有效且用途需要期间保留 | 待按数据类别、来源协议和处理目的确认 |
| `mask_map`/UID 映射 | 独立加密、最少人员、不得进入普通备份/日志 | 待确认纠错/追溯需要及删除或匿名化触发条件 |
| 缓存、临时文件、队列消息 | 完成单次处理所需的最短时间；不得作为长期存储 | 各组件 TTL 在实现前登记并验证清除 |
| ES 索引 | 仅保存检索所需的去标识化最小字段；PostgreSQL 为事实源 | 与源记录删除/下线同步并每日对账 |
| 导出包 | 最小内容、加密交付、限次且有时效 | 待 D-13 与责任单位确认最长有效期和销毁证明 |
| 审计记录 | 只增不删，至少保留 3 年 | 更长期限和可信归档机制待责任单位批准 |
| 备份 | 加密、最小访问、删除同步和可恢复验证 | 周期、保留代数及过期数据清除方式待确认 |

D-30 未批准前，禁止真实数据进入系统；合成测试数据可按测试环境清理规则随时销毁。

## 4. 个人信息保护影响评估记录

当前评估范围覆盖取得、隔离暂存、去标识化、标注、审核、发布、检索、导出、备份和删除。初步高风险场景及控制如下：

| 风险 | 影响 | 现有/要求控制 | 剩余决定 |
| --- | --- | --- | --- |
| 来源或合法基础不完整 | 非法处理敏感个人信息 | 强制授权台账；缺项失败关闭；真实数据入口关闭 | 责任主体、合法基础和授权文件批准 |
| 去标识化不足或可重识别 | 身份泄露、数据关联 | DICOM profile、像素/OCR 复核、映射隔离、私有标签默认删除 | D-37 profile/options 与重识别风险验收 |
| 越权或批量扒图 | 大规模影像泄露 | 资格 + 分派 + 逐资源鉴权；帧流、水印、限流、锁定、审计 | 阈值、解锁流程和负向测试证据 |
| 导出或内部人员滥用 | 目的外共享、不可控复制 | 默认无下载；双人审批；最小化、加密、时效链接 | D-13 导出内容及责任分离批准 |
| 日志、缓存、ES、备份形成副本 | 扩大暴露面、删除不完整 | 数据最小化、分级继承、同步删除、独立审计 | D-30/D-36 的期限和防篡改方案 |
| 凭证或密钥泄露 | 会话劫持、批量访问 | 秘密外置、分环境/用途、轮换吊销、会话撤销 | D-32/D-34 及生产 KMS 责任人 |

评估结论：风险只能在全部未决项获责任单位批准、对应控制有验证证据后重新判定为可接受。目前结论为“未放行真实数据”。评估人、责任单位批准人、批准日期、复评日期和适用数据来源均待填写；任何处理目的、数据类别、接收方或信任边界变化都必须复评。
