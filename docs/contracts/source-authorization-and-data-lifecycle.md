# 数据来源与保留最小契约

状态：2026-09-22 由项目临时负责人更新批准。源开发手册是实现范围的权威；本契约仅开放合成数据和老师提供的教学样例，不构成其他真实医学数据来源的授权。

依据：源开发手册 §4、§7.1、§8.3；[需求基线](../医学影像标注平台-需求拆解与实施基线.md) D-30、D-31、D-33。

## 当前允许来源

| `source` | 数据范围 | 授权用途 | 有效期 | 撤回处理 |
| --- | --- | --- | --- | --- |
| `synthetic` | 合成测试数据 | 本项目开发测试 | 至项目验收 | 停止导入并按需清理 |
| `teacher_provided_teaching` | 老师提供的教学样例 | 仅限本项目开发测试 | 至项目验收 | 立即停止导入，并删除已导入数据和暂存数据 |

- `cases.source` 必填并全程携带；服务端只接受上表固定值，其他来源默认拒绝。
- `teacher_provided_teaching` 由项目临时负责人于 2026-09-22 确认，授权依据记为 `project_owner_confirmation`；不据此宣称伦理、生产或对外发布条件已满足。
- 每个导入批次派生来源记录，至少包含用途、是否允许真实数据、授权依据、有效期、撤回动作、记录人和记录时间，并在批次接收和病例正式入库审计中保留最小字段。
- 不新增授权台账表、审批系统或其他业务表。当前固定来源政策由服务端白名单执行；发生撤回时先移除允许值并阻断新导入，再由项目负责人清理对应来源的 PostgreSQL、Orthanc、MinIO 和隔离暂存数据。
- 原始 DICOM、原始报告、患者信息、脱敏映射和生产备份不得进入 Git、PR、工程日志或外部服务；真实样例只能在本机隔离导入链路处理。
- 除 `teacher_provided_teaching` 外的真实数据仍保持关闭；新增来源前重新确认提供方、用途、期限和撤回处理。

## 源手册明确的保留规则

| 对象 | 最小规则 |
| --- | --- |
| PostgreSQL 业务表 | 按源手册使用软删除字段，不另建删除编排系统 |
| 审计日志 | 只增不删，保存不少于 3 年 |
| PostgreSQL 备份 | 每日 `pg_dump`，保留最近 30 份 |
| Orthanc 与 MinIO | 每日异地 rsync，或使用 OSS 版本控制桶 |
| 帧缓存 | Redis TTL 30 分钟 |
| 导入临时文件 | 单次导入任务结束后直接清理，不作为业务数据长期保存 |
| 合成测试数据 | 可由项目负责人按测试需要手工清理 |
| 老师提供的教学样例 | 至项目验收；提前撤回时停止导入并删除已导入数据和暂存数据 |

导出链接只实现源手册要求的 `expire_at` 和时效失效；具体时长在导出模块启动时确认，不在 WP-S0 提前增加规则。

## 其他真实数据重新评审条件

新增任何其他真实医学数据来源前，至少重新确认数据提供方、允许用途、有效期、撤回处理、正式分类分级和适用流程。未完成时继续拒绝该来源，不影响已批准来源的开发测试。
