# 鉴权、授权与会话策略契约（WP-S0 草案）

状态：工程基线草案；管理员 2FA、会话撤销和逐资源负向测试在 WP-02/SG-2 实现并验收。真实数据仍未放行。

依据：源开发手册 §2.2、§2.6、§3.4、§5.1、§8.4；[需求基线](../医学影像标注平台-需求拆解与实施基线.md) §8.6、D-03/D-13/D-14/D-32。

## 1. 强制校验顺序

每个受保护请求按以下顺序执行，后台任务和内部 API 同样使用最小权限服务身份：

1. 验证凭证完整性、算法白名单、签发方/受众、有效期和 `jti/token_version`；
2. 检查账号存在、启用、未过期、未锁定且未被强制下线；
3. 检查管理角色或业务资格，资格挂起立即失效；
4. 检查当前任务分派、任务角色和状态机；
5. 检查来源授权、病例/序列/帧等资源归属及资源存在性。

外部响应不得泄露无权资源是否存在；内部审计记录拒绝阶段、策略 ID 和必要资源引用，不记录凭证或敏感载荷。

## 3. 浏览器会话保守基线

D-32 正式批准前执行下列最小暴露方案：

- Bearer access token 最长有效期遵循源手册 8 小时，但只保存在页面运行内存；禁止写入 `localStorage`、`sessionStorage`、IndexedDB、URL、日志或错误报告。
- 当前阶段不定义长期 refresh token；刷新页面或关闭浏览器后重新登录。若后续引入刷新机制，必须先确认 HttpOnly/Secure/SameSite Cookie、CSRF、防重放、轮换与撤销契约。
- token 含唯一 `jti` 和账号 `token_version`；停用、过期、锁定、改密、资格挂起和管理员强制下线后，服务端检查必须立即拒绝旧 token。
- 帧 token 与登录 token 使用不同密钥/用途标识，最长 5 分钟且绑定会话和具体帧参数；不得暴露 Orthanc/MinIO 地址、桶名或对象键。
- CORS 使用明确来源白名单；任何未来 Cookie 认证都必须同时启用 CSRF 防护。CSP、输出编码和依赖扫描共同控制 XSS 风险。

该保守基线可用于 WP-02 设计；若需改变持久化或刷新体验，必须先更新并批准 D-32。

## 4. 必测拒绝路径

每个高价值接口至少覆盖：未登录、凭证过期/篡改、停用、账号过期、锁定、错误角色、错误/挂起资格、未分派、跨病例、跨序列、非法状态、授权过期/撤回、资源不存在、重放和并发竞态。帧接口还需覆盖换用户、换会话、改病例/序列/帧/window、超过 5 分钟、密钥轮换以及高速翻帧触发 429/锁定。
