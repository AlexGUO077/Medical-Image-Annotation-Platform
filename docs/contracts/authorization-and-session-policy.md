# 鉴权授权与会话最小契约

状态：D-32 已按合成数据阶段最小方案批准；管理员 2FA 采用已批准的 [D-03](../decisions/D-03-admin-2fa.md)。WP-02 按源开发手册实现和验证，不增加刷新令牌、令牌黑名单或会话管理平台。

依据：源开发手册 §2.2、§3.4、§5.1、§7.3、§8.4。

## 强制校验顺序

每个受保护请求按源手册顺序执行：

1. 验证登录凭证和 JWT 有效期；
2. 检查账号未停用且未过期；
3. 检查角色和对应系统资格；
4. 检查任务分派及任务角色；
5. 检查病例、序列或其他目标资源存在。

所有写操作在事务内完成并写审计。业务人员只能访问本人被分配的病例；已发布病例只对持对应系统资格的人员开放只读检索。

## 会话方案

- JWT 有效期固定为源手册要求的 8 小时，浏览器只在运行内存中保存 Bearer token。
- 不实现 refresh token；刷新页面或关闭浏览器后重新登录。
- 后端每次请求查询账号状态和有效期，使停用、过期和异常锁定立即生效。
- JWT 携带签发时的账号 `updated_at` 精确值；与当前数据库值不一致时拒绝请求，使改密、资格变更和管理员主动下线立即使旧会话失效。
- 不增加 `jti`、`token_version`、分布式黑名单或独立会话管理服务；后续只有源手册变更或实际缺陷证明需要时才评审。
- 管理员密码验证后必须完成 Microsoft Authenticator 兼容 TOTP；首次绑定和验证阶段只使用 5 分钟、用途受限的临时 JWT。
- 帧 token 与登录 JWT 分开配置，按源手册 5 分钟过期并绑定用户、会话、病例、序列、帧号和窗宽窗位。

### WP-07 内部票据实现

`FrameTicketService` 使用独立的 `FRAME_TOKEN_SECRET`（至少 32 字节随机密钥，不得复用 `JWT_SECRET`），固定 HS256、专用 audience 与 frame 用途，有效期精确为 300 秒。票据绑定用户 ID、当前 Bearer 的 SHA-256 摘要、病例 ID、序列 UID、帧号及窗宽窗位；不包含原始登录凭证或患者文本。相同 Bearer 视为同一会话，不新增会话表或 `jti`。`window=null` 表示使用影像默认窗口，不允许请求端另传参数覆盖票据。

目前仅提供内部签发/验证组件，尚未挂载公开路由。签发与取帧调用方均须先验证当前登录凭证和实时账号/资源权限；票据不能替代这些检查。无效、过期、换用户或换 Bearer 的票据统一返回 403。公开接口必须连同限流、异常锁定、水印、审计和权限检查接入，才可验收；内部测试通过不代表 SG-4 放行。

### WP-07 内部渲染缓存

按源手册 §7.3，Redis 仅缓存服务端渲染后的 PNG，写入时设置 1800 秒 TTL，命中不续期。键绑定病例、序列 UID、Orthanc 实例、实例内帧号和窗宽窗位；重新入库产生的新实例不复用旧缓存。缓存内容不含用户水印，禁止直接作为公开响应；权限检查、用户水印和审计必须在每次输出时执行。损坏或非 PNG 缓存从 Orthanc 重建，重建失败或 Redis 不可用时返回通用 503，不降级返回原始影像。

## 手册权限红线

| 行为 | 最小控制 |
| --- | --- |
| 原始 DICOM 或整序列下载 | 所有角色禁止；界面和 API 均不提供 |
| 标注 | 对应系统标注资格 + 当前标注分派 |
| 审核 | 对应系统审核资格 + 当前审核分派；他审时与标注人分离 |
| 已发布病例检索 | 已批准 D-29：对应系统 annotate/review 任一资格，只读且不可下载；管理员同样需资格，限已确认脱敏的 synthetic 当前发布版本；库模式帧/附件绑定版本，原工作分派模式不放宽 |
| 账号、资格和解锁 | 管理员；敏感变更写审计 |
| 导出 | 一名管理员申请，另一名管理员审批 |

## 最小测试范围

覆盖未登录、JWT 过期、账号停用/过期、错误角色、错误资格、未分派、跨病例访问和非法状态。帧接口另测 5 分钟过期、换账号/会话、篡改帧参数以及高速翻帧触发 429 和锁定。
