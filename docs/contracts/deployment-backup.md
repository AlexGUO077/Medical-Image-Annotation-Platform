# 合成部署与备份恢复契约

依据源 Word §8.1～§8.3、已批准 D-43/D-44、WP-16/SG-6。首批只验证本地 synthetic，云端/异地地址未配置；不代表公网或真实数据放行。

- 复用七个运行服务；nginx 托管前端并反代 `/api/`，仅其 HTTP/HTTPS 发布到本机回环。其余服务没有宿主端口；Orthanc 独立内部网络仅与 server 连接。
- Node 24/Python 3.11 和本地 OCR/NER 子进程打包；应用、数据库运行账号与迁移账号分离；MinIO 私有桶使用仅限本项目桶的运行凭证，ES 仅发布索引权限。运行 server 不接收 PostgreSQL/MinIO/ES 管理员秘密。
- 实例目录包含受保护的环境文件、证书及操作锁；不打入镜像或备份。实例名、固定 synthetic 数据库和回环端口在操作前校验；拒绝操作非本工具创建的实例。密钥不打印，故障仅输出步骤名称。
- `init` 创建新的隔离实例配置和本地测试证书；`up` 启动中间件、迁移/初始化最小角色后启动 server/nginx；`backup` 备份；`restore` 只还原到新建且未启动的临时实例。部署工具不自动安装定时任务或访问异地目标。
- 备份持有实例互斥锁，记录原运行状态，停止 server/Orthanc/MinIO并确认停止；PG custom dump 与两个数据卷 tar 属于同一批次，完成后恢复原运行状态。禁止在不完整停止状态下制作备份。
- 完整文件及校验清单写入临时目录，校验/恢复服务成功后才原子公布完整批次。失败保留旧备份；只对本工具成功批次保留最近 30 份 PG dump，不自动删除影像/对象备份。旧 PG dump 已被保留策略删除的批次不可作为完整恢复源。
- 可选 rsync 仅在完整批次成功后进行，使用运维者明确提供的 SSH 目标并严格校验 SSH 主机；不接收 Shell 片段，不做远端删除，同步失败返回失败。示例定时任务供人工安装。
- 恢复检查格式、每个文件的 SHA256、tar 路径/类型和目标空卷；校验失败不写目标。仅从同一完整批次恢复 PG/Orthanc/MinIO。首次恢复不启动业务入口，检查所有病例均为 synthetic 后再初始化最小账号并启动；Redis不恢复，JWT/帧密钥重新生成，MFA/映射/UID密钥由操作者独立提供；ES 从 PG 对账重建。
- TLS 测试证书不当作可信证书。真实域名签发按 certbot webroot/renew 和 nginx reload 标准流程，在具体目标确认后执行；HTTP 除 ACME 验证外 301 HTTPS，添加 nosniff/DENY，2GB 上传限制，原始服务无反代路径。代理不记录带票据的完整请求 URL。

验证包括失败停止/坏备份拒绝、空目标保护、同批数据恢复及至少 3 例通过已鉴权业务预览打开；仅文件数量/端口监听不作为通过证据。
