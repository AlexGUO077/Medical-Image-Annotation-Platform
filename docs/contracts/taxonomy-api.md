# WP-03 标签树读取接口契约

本契约对应源开发手册 §4.2、§5.2、§6.3 与需求基线 WP-03，仅定义当前 16 张业务表能够表达的读取行为。当前数据均为合成示例，不作为医学判断依据。

## GET /api/taxonomy/tree

- 认证：Bearer access token；账号停用、过期、未完成首次改密或管理员未完成 2FA 时沿用认证模块拒绝规则。
- 权限：已认证的管理员和业务人员均可读取，以供管理页、工作台和病例库复用。
- 范围：只返回 `deleted_at IS NULL` 的标签节点和征象标签。
- 顺序：节点和征象均按名称稳定排序。

响应：

```json
{
  "tree": [{
    "id": "uuid",
    "parent_id": null,
    "level": 1,
    "name": "呼吸",
    "synonyms": [],
    "icd": null,
    "children": []
  }],
  "sign_tags": [{
    "id": "uuid",
    "name": "合成示例征象-resp",
    "system_code": "resp",
    "definition": "仅用于合成数据开发验证，不作为医学判断依据。"
  }]
}
```

四级结构固定为“系统 → 部位/类别 → 疾病 → 分型/分期”。第 3 级疾病节点另含 `sign_tags`，表示该疾病所属一级系统当前可选的征象清单，并包含工作台需要的定义。源手册只定义了 `sign_tags.system_code`，没有定义疾病与征象的独立关联表，因此当前不新增第 17 张表，也不虚构更细粒度关系。

`taxonomy_nodes.synonyms` 是当前已定义的同义词来源；`sign_tags` 没有同义词字段，接口不得自行生成医学同义词。

## 暂不开放的写操作

D-28 未确认前，不提供标签节点或征象的新增、修改、移动、停用和删除接口，也不实现已引用标签处理及 ICD 唯一性规则。管理页当前仅提供读取子模块。
