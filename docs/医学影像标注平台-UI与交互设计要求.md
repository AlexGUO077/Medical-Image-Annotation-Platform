# 医学影像标注平台 UI 与交互设计要求

> 文档状态：V0.1 评审稿
> 基线日期：2026-09-18
> 适用前端：`web-anno`
> 上位文档：`医学影像标注平台-开发手册（学生版）V1.0.docx`
> 工程基线：`docs/医学影像标注平台-需求拆解与实施基线.md`
> 文档性质：用户界面与交互约束，不独立定义业务、数据、接口、安全或技术架构

执行流程统一见 [AGENTS.md](../AGENTS.md)；本文只维护 UI 与交互约束，不另设代理编排或审查轮次。

## 0. 文档目的

本文档规定医学影像标注平台面向用户的页面结构、视觉语言、组件状态、操作方式、反馈机制和可用性要求，用于指导前端设计、原型、开发、测试和验收。

本文档与源开发手册、工程实施基线共同组成项目设计核心：

1. 源开发手册规定总要求、业务功能、数据结构、接口和技术路线；
2. 工程实施基线规定架构、安全、实施顺序、待确认契约和验收门；
3. 本文档规定在上述约束内如何向用户呈现功能以及用户如何完成操作。

本文档只能细化上位文档已经要求的能力，不得删除、替换、弱化或改变上位文档中的功能和契约。参考 OHIF、Encord 等平台时，只借鉴适合本项目的界面组织和交互方式，不将参考平台的其他能力自动视为本项目需求。

## 1. 约束等级和冲突处理

### 1.1 用语

- **必须、不得**：强制要求，设计、实现和验收均不得偏离。
- **应、不应**：默认要求；确需偏离时必须说明原因并经过评审。
- **可以**：允许采用的实现方式，不构成新增业务要求。
- **待确认**：依赖工程基线中的契约决策，确认前只允许设计用户目标，不得冻结数据或接口实现。

### 1.2 文档优先级

发生冲突或歧义时，按以下顺序处理：

1. 源开发手册中的明确业务、数据、接口和技术要求；
2. 工程实施基线中的安全边界、实施约束和已确认契约；
3. 本 UI 与交互设计要求；
4. 参考产品、视觉稿、原型和设计示例。

若 UI 方案需要新增字段、枚举、接口、状态、角色、资格、业务流程或安全例外，必须停止固化设计并进入变更评审，不得以“只是界面调整”为由实施。

### 1.3 合规检查

每项新增 UI 或交互方案必须确认：

- 没有遗漏上位文档要求的功能；
- 没有新增未经批准的业务能力；
- 没有改变数据库字段、枚举、接口路径或请求语义；
- 没有改变病例状态机、任务角色和审核规则；
- 没有扩大用户可见数据范围；
- 没有削弱帧服务、水印、限流、锁定、审计、脱敏和防下载要求；
- 没有将前端显隐误当成权限或安全边界。

## 2. 设计原则

### 2.1 实用主义

平台是专业生产工具，不是消费级展示产品。设计必须优先保证：

- 主要任务路径直接；
- 影像区域充足；
- 当前工具、对象、保存和业务状态明确；
- 高频操作步骤少；
- 错误可定位、可恢复；
- 长时间工作时干扰少；
- 组件简单、稳定、便于维护。

在满足需求的前提下，不提前加入复杂配置、个性化布局、动画、多人共识、AI 辅助、复杂多视口或其他非必要能力。

### 2.2 业务事实以服务端为准

- 账号、角色、资格、任务归属、病例状态、资源关系和发布资格必须由服务端裁决。
- 前端按钮、路由和禁用状态只提供交互提示，不构成安全边界。
- 所有写入成功、状态迁移和发布结果必须以服务端响应为准。
- 前端派生的“待关联”“信息未完整”等状态不得冒充数据库枚举。

### 2.3 参考产品的使用边界

- 可以借鉴 OHIF 的暗色视口、紧凑工具栏、当前视口强调、四角信息和对象列表组织。
- 可以借鉴 Encord 的切片导航、对象选择、属性编辑、渐进反馈和高频快捷操作。
- 不得因此引入 MPR、三维渲染、Hanging Protocol、AI 自动标注、切片插值、Consensus 或自定义工作流。
- 不得照搬参考产品中的患者身份入口、影像导出、报告生成、截图、打印或共享链接。

## 3. 范围和页面

本期 UI 必须覆盖以下页面：

| 页面 | 路由 | 核心呈现 |
| --- | --- | --- |
| 登录 | `/login` | 登录、首次强制改密；管理员 2FA 界面等待 D-03 |
| 任务列表 | `/tasks` | 按任务分组的在途病例、优先级、截止时间、任务角色和领取池入口 |
| 标注工作台 | `/workbench/:caseId` | 病例与报告、影像、标注对象三区布局 |
| 审核台 | `/review/:caseId` | 工作台只读模式、逐对象批注、总体结论、通过和打回 |
| 病例录入 | `/cases/import` | 批量导入、手工简版录入、进度、失败明细和脱敏确认 |
| 病例与临床信息 | `/cases/:id` | 临床信息、自动脱敏提示、附件和教学字段补录 |
| 检索与归类 | `/library` | 四级标签树、组合筛选、全文检索和结果卡片 |
| 统计看板 | `/dashboard` | 任务、人、系统、来源和时间维度指标 |
| 系统管理 | `/admin` | 账号、资格、标签、导出审批和审计日志，仅管理员可见 |

本期不建设教学端页面，不支持动态超声视频和病理全切片 WSI。

## 4. UI 技术与主题

### 4.1 组件库

- `web-anno` 唯一通用 UI 组件库确定为 Ant Design v5。
- 不得混用 Element Plus 或另一套主组件库。
- Cornerstone3D 仅承担医学影像渲染及阅片工具能力；标注层按上位文档自研。
- UI 组件库不得改变帧服务、数据契约、状态机或权限模型。

### 4.2 双主题

采用两类主题：

- 标注工作台和审核台使用低亮度暗色主题；
- 登录、任务、录入、病例详情、检索、看板和系统管理使用浅色主题。

两类主题必须共用品牌色、状态语义、字号层级、图标体系和交互反馈。主题切换不得造成状态含义变化。

### 4.3 信息密度

- 专业页面采用偏紧凑布局，但不得通过过小字号和过小点击目标换取密度。
- 工作台优先保证影像面积和当前状态可见性。
- 表格和列表应减少装饰性留白。
- 不使用大面积渐变、发光、装饰动画或营销式卡片。

### 4.4 可调整性边界

为便于后续调整组件而不改动业务逻辑，以下内容必须集中配置，不得散落硬编码在页面中：

- 主题色、状态色、间距、圆角、阴影和字号等设计令牌；
- 左右栏默认宽度、最小宽度和最大宽度；
- 工具栏分组、图标、提示文案和快捷键映射；
- 对象色板、窗位预设和审核常用意见模板；
- 加载、空状态、错误和权限提示的通用组件。

业务枚举、资格、病例状态、标签内容和接口能力不得通过前端配置擅自扩展。页面组件应围绕稳定职责拆分，视觉替换不能改变保存、提交、审核、发布和权限语义。

## 5. 全局导航

### 5.1 结构

采用顶部栏和左侧导航结合的方式：

- 左侧导航负责页面模块切换；
- 顶部栏负责系统标识、当前页面或病例上下文、账号入口和全局状态；
- 登录页不显示业务导航；
- 菜单项必须根据服务端权限结果显示，但隐藏菜单不能替代接口鉴权。

### 5.2 左侧导航

左侧导航按权限显示任务、病例录入、病例库、统计和系统管理等入口。

- 普通页面默认展开文字标签；
- 标注和审核页面自动缩为约 48px 的图标栏，避免与工作台病例报告栏争夺空间；
- 图标栏必须提供 Tooltip；
- 当前页面必须有明确选中状态；
- 用户不能看到无权限页面的敏感数量或摘要。

### 5.3 顶部栏

普通页面顶部栏显示页面标题、必要的面包屑和账号入口。工作台顶部栏显示：

- 脱敏病例号；
- 正式病例状态；
- 年龄段、性别和系统；
- 保存状态；
- 手动保存；
- 提交审核或审核操作。

不得显示患者姓名、PatientID 或其他直接身份标识。

## 6. 全局视觉语言

### 6.1 字体

中文界面使用系统字体栈；帧号、WW/WL、坐标和其他数值使用等宽字体。

| 内容 | 建议字号 |
| --- | ---: |
| 页面标题 | 20–24px |
| 面板标题 | 16px |
| 正文、表单和按钮 | 14px |
| 紧凑表格 | 13–14px |
| 辅助说明及视口角标 | 12–13px |

正文不得低于 14px；12px 只用于辅助信息。

### 6.2 状态颜色

- 蓝色：当前选中、进行中；
- 绿色：已保存、审核通过、已发布；
- 橙色：待处理、字段不完整、离线；
- 红色：保存失败、打回、安全阻断；
- 灰色：停用、下线、只读。

状态必须同时提供文字或图标，不得只依赖颜色。

### 6.3 对象色板

V1 提供最多 12 个可配置的高区分度对象色：

`#22D3EE`、`#FACC15`、`#FB7185`、`#A78BFA`、`#A3E635`、`#FB923C`、`#60A5FA`、`#F472B6`、`#2DD4BF`、`#D9F99D`、`#C084FC`、`#FDBA74`。

- 颜色通过设计令牌维护，实施前必须在不同窗位和色弱模拟下验证；
- 对象颜色由系统稳定分配，V1 不允许用户手动修改；
- 同一对象在视口、对象列表、报告关联、切片标记和审核批注中保持同色；
- 颜色不表示疾病、严重程度、置信度或审核结果；
- 超过色板数量时可以重复，但必须通过对象编号和文字区分。

## 7. 标注工作台布局

### 7.1 三区结构

工作台必须采用：

```text
左侧病例与报告区 | 中央视口区 | 右侧标注对象区
```

左侧显示脱敏临床信息、编号报告句和附件；中部显示影像、标注叠加和水印；右侧显示对象列表及当前对象属性。

### 7.2 默认宽度

| 区域 | 默认值 | 最小值 | 最大值 |
| --- | ---: | ---: | ---: |
| 左侧病例与报告 | 300px | 240px | 420px |
| 中央视口 | 自动占满 | 640px | 不限制 |
| 右侧对象与属性 | 340px | 300px | 480px |

左右栏宽度允许通过分隔线调整；双击分隔线恢复默认值。只允许保存布局数字，不得把病例数据写入布局偏好。

### 7.3 折叠和专注模式

- 左右栏可以独立折叠；
- 折叠后必须保留可发现的恢复入口；
- 折叠不得清空选中对象、报告关联或未保存属性；
- 双栏折叠后中央影像区扩大；
- V1 提供应用内“影像专注模式”，暂不要求浏览器级 Fullscreen API；
- 专注模式必须保留工具栏、帧号、WW/WL、保存状态、水印和退出入口；
- `Esc` 可以退出专注模式。

## 8. 影像视口

### 8.1 基本要求

- 视口使用纯黑或近黑背景；
- 标注端与教学端必须使用经工程契约确认的同源渲染内核，避免“标注所见”与“学生所学”不一致；
- 所有帧必须通过安全帧服务获取；
- 不得把原始像素、原始 DICOM 或整序列写入浏览器磁盘缓存；
- 影像区必须叠加账号、姓名和时间组成的 10–15% 半透明平铺水印；
- 水印不可隐藏或调节；
- 全屏、缩放、附件预览和缩略图不得绕过水印；
- 当前帧、总帧数和 WW/WL 必须就近显示。

四角信息只允许来自经过授权、去标识化的工作台数据，不显示直接身份标识。

### 8.2 序列和切片导航

- 多序列使用简单的序列 Tab 或选择器；
- 单帧影像不显示无意义的切片滑块；
- 多帧影像显示当前帧、总帧数和切片滑块；
- 滑轨可以用对象色小标记显示已有标注的帧位置；
- 点击标记跳转到对应帧；
- 滚轮和方向键仍是主要翻层方式；
- 在正常网络和服务条件下预取相邻帧，以满足核心文档规定的翻层响应 ≤ 200ms 目标；预取仍须经过帧服务且只使用受控内存缓存；
- V1 不提供 2×2 多视口、MPR、Crosshair 或同步视口。

## 9. 视口工具栏和输入方式

### 9.1 工具栏

中央视口上方设置分组式水平工具栏：

```text
标注工具 | 阅片工具 | 显示设置 | 视口操作
```

- 标注：矩形、画笔、多边形、点；
- 阅片：窗宽窗位、平移、缩放、测量；
- 显示：窗位预设、标注透明度；
- 视口：重置视图、专注模式、快捷键帮助。

保存和提交属于病例级操作，放在页面顶栏。工具栏不得出现截图、下载、打印、复制原始地址或影像导出。

### 9.2 默认模式

进入、刷新或切换病例时默认进入浏览／窗宽窗位模式，不保留上一病例的危险绘制工具。

### 9.3 鼠标和快捷键

| 输入 | 行为 |
| --- | --- |
| 左键拖动 | 当前激活工具；浏览模式下调整窗宽窗位 |
| 滚轮或 `↑/↓` | 翻层 |
| 中键拖动 | 平移 |
| 空格 + 左键拖动 | 平移备用方式 |
| 右键拖动 | 缩放 |
| `1/2/3/4` | 矩形、画笔、多边形、点 |
| `W/P/Z/M` | 窗宽窗位、平移、缩放、测量 |
| `R` | 重置视图 |
| `[` / `]` | 调整画笔直径 |
| `Esc` | 取消绘制或返回浏览模式 |
| `Delete/Backspace` | 删除选中对象 |
| `Ctrl/⌘ + Z` | 撤销 |
| `Ctrl/⌘ + Shift + Z` | 重做 |
| `Ctrl/⌘ + S` | 手动保存 |

输入框、报告文本和下拉搜索框获得焦点时，普通字母、数字及删除快捷键不得触发视口操作。只读、锁定和已发布状态下，修改类快捷键必须失效。

### 9.4 工具状态

- 每次只能激活一个主要工具；
- 激活状态必须同时使用背景、边框、图标或文字表达；
- 工具按钮 Tooltip 必须显示名称和快捷键；
- 画笔光标必须显示实际作用范围；
- 锁定对象不显示控制柄且不能被拖动；
- 测量只是阅片辅助，不构成第五种业务标注类型。

### 9.5 四类标注工具

| 工具 | 最小交互要求 |
| --- | --- |
| 矩形 | 按下并拖动创建；选中后拖动边和角控制柄调整 |
| 画笔 | 光标显示实际作用范围；直径按毫米调节；提供橡皮擦对当前帧掩膜回修 |
| 多边形 | 逐点或自由手绘形成闭合区域；支持结束、取消、删除末点和选中后的顶点编辑 |
| 点 | 单击创建；选中后允许拖动微调位置 |

- 无效的零面积矩形、未闭合多边形和落在影像范围外的结果不得创建对象；
- 工具切换、切换序列、退出页面或按 `Esc` 时，未完成绘制必须先取消或明确确认，不得生成半成品对象；
- 所有几何数据使用左上角为原点的 DICOM 像素坐标；缩放、平移和屏幕尺寸只属于显示变换，不得写入业务几何；
- 画笔逐帧数据、掩膜编码以及其他几何结构必须遵守既有 `annotation_objects.geometry` 契约。

## 10. 标注对象与属性

### 10.1 对象显示

- 普通矩形、多边形和点使用约 2px 对象色轮廓及暗色外阴影；
- 画笔掩膜默认使用低透明度填充并保留轮廓；
- 选中对象保留对象色，同时增加高对比外轮廓和编辑控制柄；
- 锁定对象保留原色，显示锁图标和文字，不显示编辑控制柄；
- 隐藏对象从视口消失，但仍保留在对象列表并显示闭眼图标；
- 字段错误、保存错误和审核问题不得覆盖对象身份颜色。

### 10.2 右侧面板

采用简单的“紧凑对象列表 + 下方固定属性区”。不提供内部高度调整、复杂筛选、卡片布局切换或个性化字段排序。

对象列表每项显示：

- 对象颜色和稳定编号；
- 工具类型；
- 部位；
- 主要征象；
- 帧范围；
- 显示／隐藏；
- 锁定；
- 信息未完整或有审核批注提示。

点击对象后必须同步选中视口轮廓、定位帧、定位报告句，并在下方显示属性。

### 10.3 属性区

属性区显示：

- 工具类型和所属序列，只读；
- 部位；
- 至少一个征象；
- 置信度，只能为典型／不典型；
- 代表帧与起止帧；
- 报告关联模式和摘要；
- 允许的测量信息。

部位选择受 D-07 约束，代表帧受 D-06 约束。确认前不得自行新增字段。

征象选择支持按名称和同义词搜索，并提供定义或标注规范的就近查看入口；内容来自 `sign_tags.definition`，前端不得自行编写医学解释。

### 10.4 创建和批量删除

- 完成一次有效绘制后自动创建并选中对象；
- 新对象出现在列表末尾，提示补齐部位、征象和置信度；
- 属性未完成时允许保存草稿，但提交审核时必须阻断；
- V1 只为批量删除提供批量选择；
- 不提供批量修改医学属性；
- 批量删除必须确认并进入正常版本和审计流程。

工作台必须提供“复制当前轮廓到相邻帧”操作：用户明确选择前一帧或后一帧，复制后立即进入微调；不得自动扩散到整段切片，不得跨序列复制。保存方式、版本递增和帧范围必须沿用既有标注契约。

### 10.5 模态差异

- CT：显示并记录窗位预设；对象支持代表帧和起止帧；
- MR：创建对象前必须明确所属序列，对象始终挂在病灶最清楚的具体序列；
- 胸片正侧位和乳腺 CC/MLO：各视图作为独立序列，病例级疾病标签与视图级标注对象分开表达；
- DR 和单帧超声：按单帧处理，不显示无意义的多帧控件。

## 11. 报告关联

### 11.1 报告面板

左侧采用“临床信息／报告／附件”页签，工作台默认打开报告。报告必须只读、已脱敏并按稳定 `idx` 保持原始顺序显示。

未选择对象时，可以阅读报告但不能创建归属不明的关联。

### 11.2 句子状态

- 普通句使用中性样式；
- 候选句根据当前对象部位、征象名称和同义词高亮，显示“候选”文字；
- 候选句不得自动关联或被表述成诊断结论；
- 已关联当前对象的句子使用对象色竖条、对象编号和轻量背景；
- 已关联其他对象的句子显示相应对象编号 Chip；
- 阴性句显示“阴性”文字标签；
- 鉴别句显示“鉴别”文字标签；
- “不除外”“考虑”“可能”等表达不得自动归为阴性。

阴性和鉴别分类只用于执行已经确定的豁免规则，最终提交校验仍由服务端完成。

### 11.3 建立关联

1. 用户选中对象；
2. 候选句高亮；
3. 点击句子建立关联；
4. 对象列表同步显示句号 Chip；
5. 再次点击取消关联；
6. 变更进入正常自动保存流程。

对象和报告必须支持双向定位：对象定位关联句；句子上的对象 Chip 定位对象和帧。

### 11.4 报告未提及

“报告未提及”必须位于右侧对象属性区，与“关联报告句”构成对象级互斥单选：

```text
关联报告句 / 报告未提及
```

- 选择“报告未提及”时显示明确 Chip；
- 若已有句子关联，切换前提示将清除关联；
- 不得通过空数组自动推断；
- 具体保存表示等待 D-08 确认。

### 11.5 提交检查

提交前按对象列出缺失的部位、征象、置信度和报告关联。点击问题必须定位到相应对象和面板。前端检查通过后仍必须执行服务端校验。

## 12. 保存、离线和冲突

### 12.1 保存状态

顶栏持续显示：

- 已保存及时间；
- 有未保存修改；
- 正在保存；
- 离线、本地暂存；
- 保存失败、点击重试；
- 版本冲突。

自动保存成功不弹 Toast；失败、离线、权限变化和冲突必须持续提示。

### 12.2 自动和手动保存

- 有效几何或属性操作结束后防抖 2 秒自动保存；
- 保存请求必须串行，不能乱序覆盖；
- 保存期间的新变化进入下一批；
- 手动保存立即刷新当前队列；
- 提交审核前必须完成全部保存；
- 保存成功、版本递增和最终状态以服务端响应为准。

### 12.3 离线草稿

离线时可以继续编辑允许本地暂存的数据，但提交审核、通过、打回和发布必须禁用。

本地草稿不得包含原始 DICOM、原始像素、未脱敏报告、直接身份信息、映射关系、帧 token 或长期凭证。存储范围、加密、保留期和清理方式等待 D-26。

恢复网络或重新登录后，必须重新检查会话、资格、任务、病例状态和服务端版本，校验通过后才同步。

### 12.4 版本冲突

发现冲突时暂停自动保存并提供：

- 查看差异；
- 采用服务器版本；
- 保留本地草稿。

V1 不自动合并同一对象的几何修改，不向普通用户提供强制覆盖服务器功能。版本对比和差异能力依赖 D-05。

## 13. 审核台

### 13.1 基本模式

审核台复用工作台布局，但标注、属性和报告关联保持只读。保留窗宽窗位、翻层、平移、缩放、测量、显隐、重置和专注模式。

顶栏必须显示自审、他审或抽检。进入“审核中”的状态时点等待 D-10，前端只显示服务端正式状态。

### 13.2 一票否决检查

右侧固定显示：

- 脱敏是否合格；
- 确诊依据是否完整；
- 疾病标签是否正确。

任一项不合格、缺失或错误时必须禁止通过并要求打回。具体结果如何进入 `reviews.comments` 需要在接口载荷中确认，但不得新增第三种审核结果。

### 13.3 批注

采用：

- 可配置常用意见模板；
- 逐对象自由批注；
- 总体结论。

不增加对象级“通过／不通过”状态和复杂审核原因枚举。打回时必须至少提供一条可执行的修改意见。批注至少关联对象、文字、审核人员和时间；若持久化帧号或报告句引用，必须先确认 comments 结构。

### 13.4 版本对比

V1 采用单视口叠加：

- 当前版本为对象色实线；
- 上一版本为同色虚线和较低透明度；
- 显示清晰图例；
- 不提供双视口对比。

实施依赖 D-05。

### 13.5 打回和通过

打回前显示一票否决项、涉及对象、批注数量和总体结论摘要。成功后病例回到标注中，标注人员可以从批注定位对象、帧和报告句。

通过前必须完成一票否决检查并二次确认，明确说明通过后病例发布、对象锁定为金标准、教学端按权限可读，继续修改前必须先下线。成功后页面立即进入已发布只读状态。

## 14. 病例导入

### 14.1 页面结构

`/cases/import` 使用两个页签：

- 批量导入；
- 手工简版录入。

两个页签分别使用独立 Steps，不把两种录入方式混在一个向导中。

### 14.2 批量导入步骤

```text
数据来源
→ 选择文件
→ 上传与安全检查
→ 解析与脱敏
→ 人工确认
→ 导入结果
```

- 数据来源必须在上传前选择；
- 浏览器不得解压或预览原始 DICOM；
- 上传进度与服务器处理进度必须区分；
- 没有精确进度时不得显示虚假百分比；
- 服务端返回批次号后显示真实异步状态；
- 批次处理不因用户离开页面而被前端取消。

### 14.3 处理进度

显示总计、处理中、待人工确认、成功、重复跳过和失败数量。单病例以批次临时编号或脱敏病例号显示，不显示原始 PatientName 或 PatientID。

阶段可以映射为安全检查、解析与分组、查重、去标识化、OCR、报告脱敏与分句、预分类和入库，但不得伪造后端没有返回的状态。

失败明细采用简单表格显示批次临时编号、失败阶段、安全错误码、可理解原因和建议动作。仅当服务端明确返回可重试时显示重试入口；单例重试不得重复导入已成功病例，也不得暴露原始患者标识、对象键、内部路径或堆栈。

### 14.4 人工确认

使用待确认列表、带水印的处理后影像预览和脱敏检查区。只展示去标识化结果，不提供原始 ZIP、原始标签、原始报告或原始 DICOM 下载。

OCR 命中、阈值和失败处理遵守已批准 D-17；DOCX/XLSX 附件安全预览遵守已批准 D-19。

低置信度预分类进入人工分诊，选择范围只允许八大系统编码。人工确认和分诊结果必须写审计。

完成导入前必须由有权限的用户显式确认脱敏结果；确认文案说明其责任和后续动作，但不得用前端勾选替代服务端脱敏校验、安全扫描和审计。

### 14.5 手工简版录入

手工录入使用“数据来源、报告文本、关键影像、脱敏确认、完成”步骤，仅承载核心文档规定的报告文本和一张 JPG/PNG 关键影像。按已批准 D-16，影像作为附件保存，不生成 Study/Series，不向该病例补 DICOM。

## 15. 其他页面

### 15.1 登录

- 不提供公开注册；
- 显示用户名、密码和登录操作；
- 首次登录必须进入强制改密；
- 认证失败不泄露账号是否存在；
- 管理员 2FA 绑定、验证和恢复界面等待 D-03；
- 不使用患者影像作为装饰性背景。

### 15.2 任务列表

- 使用按任务分组的卡片式紧凑列表；
- 显示优先级、截止时间、任务角色、病例状态和领取池入口；
- 标注池和审核池清楚区分；
- 不显示超出用户资格和任务范围的病例；
- 领取、锁定、回收和在途上限行为以服务端结果为准。

### 15.3 病例与临床信息

- 显示临床信息粘贴框、年龄段、性别、确诊方式、附件和教学字段；
- 保存前自动脱敏由服务端完成；
- 只有接口返回安全统计时才显示“遮蔽 N 处”等数量；
- 支持按既有契约上传附件；附件预览必须只读并带水印；
- 附件类型和大小遵守上位文档。

### 15.4 检索与归类

- 左侧四级标签树，右侧筛选和结果；
- 条件至少包括系统、部位、疾病、征象、模态、来源和报告全文；
- 结果卡片包含缩略图、诊断和征象标签；
- 缩略图必须经过安全帧服务、权限检查和水印；
- 只返回用户有资格查看的已发布病例；
- 下线或授权失效后立即不可继续查看。

### 15.5 统计看板

- 覆盖任务、人、系统、来源和时间维度；
- 显示完成量、打回率和抽检合格率；
- 优先使用少量指标卡、趋势图和明细表；
- 不堆积无业务用途的装饰性图表；
- 数据权限与服务端一致。

### 15.6 系统管理

按账号与资格、标签、导出审批和审计日志组织。

- 账号操作显示启停、有效期和资格；
- 资格使用按八大系统组织的双列选择器展示 annotate/review 能力；按已批准 D-20，本期录入仅限管理员，不新增“录入”资格；
- 导出申请人与审批人必须不同，申请人不能看到可审批自己的按钮；
- 审计记录不可编辑或删除；
- 管理接口缺口受 D-12 约束；
- 敏感操作需要的 2FA 或近期认证等待 D-03。

## 16. 全局反馈

### 16.1 五级体系

| 层级 | 用途 |
| --- | --- |
| 字段级 | 单一字段错误 |
| 区域级 | 面板、表格、视口加载或失败 |
| 页面级 | 无权限、资源不存在、页面加载失败 |
| 临时全局 | 简短、非关键成功反馈 |
| 阻断决策 | 发布、打回、冲突、放弃草稿等必须决策的动作 |

能在原位置解释的问题不得使用弹窗；普通自动保存成功不得反复提示。

### 16.2 加载与空状态

- 页面首次加载显示框架和骨架；
- 表格翻页不应整页闪白；
- 视口保留黑色背景和真实帧加载信息；
- 空状态必须说明原因和可执行的下一步；
- 无权限不得伪装成无数据。

### 16.3 429

帧服务返回 429 时：

- 保留当前帧；
- 暂停相邻帧预取；
- 在视口内持续提示访问过于频繁、请稍候；
- 有允许重试时间时显示倒计时并自动恢复；
- 不反复弹窗或绕过限流；
- 账号锁定时停止帧请求并提示联系管理员。

### 16.4 离线、会话和权限变化

- 离线使用持续横幅，禁用服务端状态迁移动作；
- 会话过期时按允许范围保存草稿并跳转登录；
- 重新登录后重新校验资格、任务和版本；
- 任务回收或资格挂起时立即停止编辑并切为只读或退出；
- 错误信息不得泄露患者信息、堆栈、路径、对象键、token 或内部服务信息。

### 16.5 服务异常

- 局部接口失败时优先保留页面框架、当前安全数据和用户上下文，在故障区域提供重试；
- 视口帧加载失败不得清空已经保存的对象列表，也不得把失败帧当作空白影像；
- 整页无法继续时显示明确原因类别、建议动作和返回安全页面入口；
- 需要排障时可以显示不含敏感信息的请求编号，不向用户暴露堆栈和内部服务拓扑；
- 对提交、通过、打回和发布等动作，响应未知时不得直接宣告成功或重复提交，必须先查询服务端最终状态。

## 17. 屏幕与无障碍

### 17.1 设备范围

- V1 是桌面浏览器专业工具；
- 工作台推荐 1920×1080 显示器；
- 最低支持浏览器内容区 1280×720；
- 普通管理页面最低支持浏览器内容区 1024×720；
- V1 不支持手机标注；
- 小于工作台最低宽度时提示扩大窗口并默认折叠一个侧栏，不得删除功能。

### 17.2 控件和键盘

- 常用工具按钮不小于 36×36px，次级图标按钮不小于 32×32px；
- 所有非影像操作应支持键盘；
- 焦点必须清晰可见；
- Modal 打开后焦点进入弹窗，关闭后返回原按钮；
- 提供快捷键帮助入口；
- 用户不记快捷键也必须能够完成任务。

### 17.3 对比和色弱

- 非影像 UI 以 WCAG 2.2 AA 为设计目标；
- 正文与背景对比度应达到 4.5:1；
- 控件边界和焦点应达到 3:1；
- 对象必须同时使用颜色、编号、图标和文字；
- 色板必须进行红绿色弱、蓝黄色弱和灰度测试；
- 保存、离线和错误状态应被辅助技术感知，但自动保存成功不应频繁朗读。

### 17.4 视口文字等价入口

Canvas 或 SVG 不得成为获取标注信息的唯一方式。对象列表必须提供对象属性、帧范围、报告关联、锁定和错误等文字信息。当前帧、总帧、WW/WL、当前工具和只读状态必须可读。

## 18. 安全与隐私红线

所有页面必须遵守：

- 标注和审核账号无原始 DICOM、整序列、批量分片或原始像素下载入口；
- 不提供打印影像、截图工具、复制原始地址或关闭水印；
- 前端不得直接访问 Orthanc、MinIO、数据库或 Elasticsearch；
- 影像只通过帧票据和短时签名 URL 获取；
- 附件预览同样带水印；
- 发布、打回、导出审批、权限变更等动作按要求确认并审计；
- 隐藏按钮不能代替服务端权限；
- 已发布金标准只读，修改前必须先下线；
- 日志、错误和 UI 状态不得包含敏感凭证和患者身份。

## 20. 明确不纳入当前版本

- 2×2 或更多多视口布局；
- MPR、Crosshair、MIP 和三维容积渲染；
- AI 自动分割、AI 预标注和模型交互；
- 自动切片插值和复制到全部帧；
- 多人 Consensus 标注；
- 自定义 Hanging Protocol；
- 手机标注、触控笔专用交互和语音控制；
- 用户自定义对象颜色和全部快捷键；
- 浏览器级全屏；
- 教学端页面；
- 普通标注或审核人员的影像导出、下载、截图和打印。

上述内容若未来需要实施，必须单独进入需求和契约变更评审，不能仅凭参考平台具备该功能而加入。

## 21. UI 验收检查表

### 21.1 全局

- [ ] 页面、路由和功能没有遗漏源开发手册要求。
- [ ] 只使用 Ant Design v5 作为通用 UI 组件库。
- [ ] 工作台和审核台暗色，其他业务页面浅色。
- [ ] 所有业务状态使用正式枚举，不用展示文字参与逻辑判断。
- [ ] 加载、空、失败、无权限、离线和会话过期状态完整。
- [ ] 无权限状态不泄露资源存在性和敏感摘要。

### 21.2 工作台

- [ ] 三区布局、左右栏调宽、折叠和专注模式可用。
- [ ] 四种标注工具和快捷键可用。
- [ ] 翻层、窗宽窗位、缩放、平移和测量可用。
- [ ] 对象显示、隐藏、锁定和批量删除可用。
- [ ] 部位、征象、典型／不典型和帧范围完整。
- [ ] 报告句双向关联及“报告未提及”显式选择可用。
- [ ] 自动保存、手动保存、离线提示和冲突阻断符合要求。
- [ ] 缩放和平移不改变存储的 DICOM 坐标。

### 21.3 审核

- [ ] 审核台标注只读。
- [ ] 三项一票否决检查完整。
- [ ] 逐对象批注和总体结论可用。
- [ ] 打回后批注可定位并保留。
- [ ] 通过需要二次确认并立即进入发布只读状态。
- [ ] 自审、他审和抽检资格由服务端判定。

### 21.4 导入与安全

- [ ] 数据来源在上传前必选。
- [ ] 异步进度、重复跳过和单例失败清楚区分。
- [ ] 人工确认只展示去标识化且带水印的数据。
- [ ] 影像和附件预览水印完整且不妨碍观察。
- [ ] 标注和审核账号全部页面没有原始影像下载、打印和导出入口。
- [ ] 429、锁定、会话撤销和权限变化有专门反馈。
- [ ] 浏览器存储中不存在原始帧、整序列、原始 DICOM 或未脱敏数据。

## 22. 变更管理

UI 设计变更必须记录：

- 变更内容和原因；
- 对应页面和用户角色；
- 引用的上位需求；
- 是否影响字段、接口、状态机、权限或安全控制；
- 合规检查结论；
- 原型或截图；
- 测试和验收证据。

纯视觉调整可以在不改变契约的前提下评审实施。任何涉及业务、数据、接口、权限或安全边界的变更，必须先更新上位契约并通过评审，再修改 UI。
