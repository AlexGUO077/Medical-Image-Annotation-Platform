# D-42 统计看板指标最小口径

状态：待用户确认；以下是可评审方案，不作为已批准要求。

依据：源 Word §2.1/§2.2/§5.2/§6.1 要求管理员工作量与质控看板、`GET /api/stats`、任务/人/系统/来源/时间维度的完成量、打回率、抽检合格率；需求基线 WP-13、UI §15.5。手册未固定指标计量单位、比例分母、人员归属和统计时间口径。按 AGENTS.md §2，业务契约缺口先确认，受影响的指标聚合和页面暂不实施。

## 提议口径

1. **完成量**：时间范围内普通审核通过的病例版本数；同一病例重标后新版本通过另计一次，抽检/全面复核通过不重复计完成。**打回率**：普通审核打回次数 / 普通审核已作结论总次数。保留通过/打回/总次数原数，比例由原数计算，展示不得平均各组百分比。
2. **人**：三个指标都归属该病例版本的提交标注人，从既有 `annotations.submitted` 审计读取；不把审核人混入同一人员指标。**抽检合格率**：spotcheck 已作结论中通过次数 / spotcheck 已作结论总次数；全面复核 recheck 不进入该分母，待派/待审核不当作失败。无已完成样本时比例为 null，页面显示“暂无”。
3. **时间与范围**：按审核结论创建时间，以北京时间（Asia/Shanghai）自然日筛选/聚合；日期范围含起止两天，默认最近 30 个自然日，包含今天。历史通过/打回继续计入，不因后续下线或重启改变已经发生的结论；未确认脱敏、非 synthetic、已软删除病例及已软删除任务不纳入本批。人员停用、资格变化不抹除历史工作量。

管理员只读访问（源手册已明确），成员接口 403，页面隐藏并由路由及服务端守卫拒绝。仅返回数量、比例和必要任务/账号标识，不返回病例临床/报告、标注几何、审计 IP、附件或存储键；不新增下载/导出。管理员看板不需要阅片资格，因为本接口仅汇总管理员管理范围，不授予病例阅片权限。

## 预期接口与最小实现

`GET /api/stats` 拟接受 `task_id`、`person_id`（提交人）、`system_code`、`source`、`from`、`to`（YYYY-MM-DD）、`group_by=task|person|system|source|day`、`page`、`pageSize`；条件 AND，from/to 成对提供。分页默认 20/最多 100；按分组稳定键排序。总览与趋势覆盖完整已过滤范围，分组明细由服务端分页；不会用当前页合计冒充总量。响应拟为 `{filters,summary,trend,items,page,pageSize,total}`，各指标同时返回原始计数及 null 或 0～1 的比例；summary 独立计算。趋势按日补齐零值。

利用已存在的 `reviews`、`audit_logs`、任务/病例/账号关联，由普通审核和质量审核的 `reviews.decided` 审计绑定任务、版本、类型及审核记录，再按相同任务/版本的提交审计绑定标注人；不依赖当前分派或当前标注版本重算历史归属。关联需要现有审计提供可信任务、版本及提交人；不依赖推测归属，实际发现缺失时再处理，不预建数据治理机制。

无新表、服务、持久统计缓存、定时统计任务或图表运行依赖；PG 聚合，前端采用既有 Ant Design 指标卡、简单 SVG 日趋势和分页明细。方案确认后先固定接口 mock，再接页面；只有确有必要的数据库约束/索引缺口才先加迁移。

验证重点：普通审核/抽检/全面复核不混计；返工/重启版本；人/任务历史归属；下线/资格变化与软删除；空分母；北京时间跨日边界；组合筛选与全量 summary/分页；成员、停用/过期管理员拒绝；DX/CT 合成 PostgreSQL/Nest HTTP 及浏览器。PR #51 合并不推定 WP-11/SG-5 或统计验收完成。
