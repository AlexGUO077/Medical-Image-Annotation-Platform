# D-28 标签管理最小规则

## 状态

已批准，2026-09-21 生效。实现仍须经过郝鹏翼老师的权限改动组长复核后方可合并。

## 决策

- 八大系统一级根节点固定，不提供新增、修改、移动、停用或删除操作。
- 管理员可新增和编辑第 2～4 级节点的名称、同义词和可选 ICD；层级由父节点推导，创建后不支持移动。
- 管理员可新增和编辑征象名称、所属系统及定义。
- 删除采用现有 `deleted_at` 软删除。只允许删除无子节点且未被业务数据引用的第 2～4 级节点，或未被标注引用的征象；存在子节点或引用时返回冲突。
- 沿用现有唯一约束：活跃标签节点按“层级 + 名称”唯一，活跃征象按“系统 + 名称”唯一。ICD 为可选信息，不增加唯一约束。
- 所有成功写操作在同一数据库事务内写入审计日志；审计详情只记录变更字段，不记录凭据或患者数据。
- 疾病可用征象继续按所属一级系统与 `sign_tags.system_code` 关联，不新增疾病征象关联表。

## 接口与权限

- 写接口及管理列表必须先在 [标签树接口契约](../contracts/taxonomy-api.md) 固定方法、路径、载荷、分页和错误语义。
- 所有写接口必须同时通过服务端登录态、账号状态和管理员角色校验。前端隐藏入口或路由重定向只作交互提示，不能代替服务端权限。

## 边界

- 不新增业务表、审批流、标签版本系统、移动能力或独立停用字段。
- 不自行生成正式医学标签、征象定义、同义词或 ICD 内容；当前自动化验证只使用明确标记的合成数据。
- D-12 仅在标签管理接口范围内由本决策和接口契约落实，其他管理接口仍按各自工作包确认。

## 回滚

回退标签写接口和管理界面；写入的数据保留在现有表中，必要时由管理员按本决策的软删除规则停用，不直接物理删除。
