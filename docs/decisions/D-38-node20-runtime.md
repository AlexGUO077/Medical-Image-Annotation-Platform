# D-38 Node.js 20 运行时决策

## 状态

已批准，2026-09-18 生效。

## 决策

项目遵循源开发手册，后端和前端构建运行时使用 Node.js `20.20.2`。NestJS 固定在支持 Node 20 的 11.x 主版本，Vite 固定在支持 Node 20.19 及以上的 7.x 主版本。

## 依据

- 源开发手册将 Node 20 列为技术栈硬约束；
- 用户于 2026-09-18 明确要求遵循手册使用 Node 20；
- npm 官方注册表显示 NestJS 11.x 支持 Node `>=20`，Vite 7.x 支持 Node `^20.19.0 || >=22.12.0`。

## 已知风险

Node 20 已于 2026-03-24 结束官方维护，不再获得上游安全修复。继续使用可能产生运行时、基础镜像或依赖生态的严重/高危问题，并可能影响安全审计结论。

## 强制控制

1. `.nvmrc`、根 `package.json`、CI 和容器镜像统一使用 `20.20.2`，避免开发、测试和构建环境漂移；
2. 每次 PR 执行依赖、基础镜像和文件系统安全扫描；
3. 本决策不自动批准任何漏洞例外；严重或高危问题仍按 SG-1、SG-6、SG-7 阻断阶段完成、合并或上线；
4. 若确需漏洞例外，必须单独记录风险、影响范围、缓解措施、批准人和失效日期；
5. WP-16 生产化开始前重新评估 Node 20 的可支持性；没有可接受的持续安全支持方案时，不得以本决策直接证明生产可用。

## 未采用方案

- Node 24 LTS：安全维护状态更合适，但与用户本次“遵循手册使用 Node 20”的决定不一致；
- 开发使用 Node 20、生产使用其他版本：环境不一致，增加不可复现风险；
- 忽略运行时漏洞：违反项目安全门和证据放行原则。

## 回滚与变更

如后续批准升级运行时，先更新本决策、工程基线、容器与 CI 契约，再通过独立变更迁移。不得只修改镜像或 CI 而保留其他环境为 Node 20。
