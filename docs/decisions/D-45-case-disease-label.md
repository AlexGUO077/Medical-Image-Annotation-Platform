# D-45 病例级疾病标签维护入口

状态：待用户确认。2026-10-08 WP-17 本地闭环准备发现实际缺口；不把方案记录当成批准。

## 依据与缺口

源 Word §2.5 将疾病标签挂在病例级，§4.2 定义 `cases.disease_tag_id` 为单一主诊断疾病标签，§6.3/§8.4/§9.3 要求审核与完整闭环。已批准 D-11 要求审核通过前确认疾病标签；现有审核校验拒绝空标签、失效标签或跨系统标签。

当前 ZIP/手工确认均未写入疾病标签，病例详情与临床信息接口也未提供维护入口。既有分段审核集成测试直接在合成夹具中设置此字段，不能证明真实录入病例能够发布。正式闭环测试不得用直接写库补标签来绕过缺口。

## 待确认最小方案

- 管理员在现有病例详情的临床信息表单选择一个疾病或分型；沿用 `PUT /api/cases/{id}/clinical`，新增可选 `disease_tag_id`，省略保留原值。`GET /api/cases/{id}` 返回当前标签标识和名称用于回显。
- 沿用现有管理员鉴权及编辑状态：仅“已录入/待分配”可编辑，不赋予标注/审核人员额外修改权限。标签缺失或错标已进入标注时，管理员通过现有回收分派回到“待分配”，修正后重新分派；不新增状态或审批流程。
- 与审核共用相同有效性口径：当前病例所属系统下的有效三级疾病或四级分型，祖先节点也有效；拒绝跨系统、已删除、部位/系统节点。不增加新表、模型或服务。
- 显式提供标签时必须为有效 UUID，不提供清空操作；保存与审计同一事务，审计只记录标签标识变化，不记录临床原文。临床文字仍走既有脱敏。
- 标签仍是手册规定的病例级字段，不扩展为标注几何或另建标签版本表。已发布/审核中等原有不可编辑状态继续拒绝。

## 验证范围

标签空缺的现状复现；管理员与 member 边界；同系统三级/四级接受，跨系统/删除节点/非法层级拒绝；状态限制、旧客户端省略保留、审计失败回滚；详情选择与回显；经真实 HTTP 录入的 X 线/CT 通过表单/接口维护标签后完成提交、审核与检索。代码修改须待本方案确认。
