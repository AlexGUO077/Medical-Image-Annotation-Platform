- 一个任务只绑定一个来源和一个系统；病例在任务间隔离，只有脱敏确认完成的病例可进入任务。

## D-09 建议：在途限额与领取期限

以下数值为开发阶段建议，源手册没有给定默认值。

| 项目 | 建议方案 |
| --- | --- |
| 任务级上限 | 每人每任务默认 5 例，在 `tasks` 增加配置字段，由管理员设置 |
| 人员全局上限 | 每人跨任务默认 10 例，在 `users` 增加配置字段，由管理员设置 |
| 计数口径 | 标注和审核的有效在途分派合计；一次新增必须同时满足该任务与全局剩余额度，不能只比较两个配置值 |
| 领取期限 | 默认 24 小时，任务可配置；领取/派单时写入现有 `due_at`，将其作为独占分派截止时间，不另造短租约系统 |
| 续期 | 不因打开页面或自动保存延长；管理员可显式延期并记录审计 |
| 超时 | 服务端定时回收；每次资源访问/写入也检查到期，不能等待定时回收才拒绝旧承接人 |
| 回收结果 | 标注中回到待分配，审核中回到待审核；已有标注版本保留，失效分派保留历史但不再授权、不计在途 |
| 资格挂起 | 资格更新与受影响分派释放在同一事务完成；仅释放失去对应系统/角色资格的在途分派 |

待批准的解释：任务级上限指“每人每任务”上限。另一种解释是“任务所有人员合计容量”，两者不能混用；建议前者，直接控制个人囤积病例。

不将同一病例跨角色的历史记录删除后重建。分派状态枚举、有效唯一约束、字段边界和迁移回滚在批准后写入数据库及任务接口契约；并发分派同时锁定病例和人员额度，避免不同病例并发派给同一人时突破上限。

## D-10 建议：进入审核中时点

- 进入待审核时按源手册生成审核分派或审核池待领项；仅生成/预分派不自动进入审核中。
- 审核池领取成功即进入审核中；已指定审核人的病例通过显式“开始审核”写请求进入审核中。只读 GET 或打开详情不改变状态。
- 放弃、回收或超时回到待审核，保留标注和已有审核记录，原分派立即失去权限。
- 自审无审核资格时提交失败并提示管理员处理，不自动切换审核模式。重交时复用/激活审核分派的具体事务在 WP-10 接入；WP-06 不提前开放绕过完整性校验的提交入口。

## D-23 建议：自动派单顺序

- 默认自动派单；只从账号有效、资格匹配、有剩余额度且满足标审分离的人员中选择。
- 先按全局有效在途量升序，再按该任务有效在途量升序，最后按用户 ID 稳定排序；不新增轮转记录或调度服务。
- 待派病例按任务优先级降序、入任务时间升序、病例 ID 排序。优先级只影响尚未分配的病例，不抢占已领取工作。
- 没有合格人员时保留待分配/待审核并在对应领取池等待，返回明确的未分派原因，不绕过限额或资格。

## D-12 在 WP-06 的接口补齐范围

保留源手册的 `POST /api/tasks` 和 `POST /api/tasks/dispatch`。批准上述业务语义后，任务接口契约需明确任务列表/详情、池列表、领取、回收、延期、开始审核，以及管理员限额配置的路径、载荷、分页、错误码与权限；不在本次补齐其他模块的管理接口。

领取池列表仅返回选择任务和领取所需的最小元数据；未领取者不能通过池列表读取报告、临床详情或影像。现有分派鉴权只检查记录存在，接入 WP-06 时须同时校验有效状态、截止时间、任务归属与病例状态，并用于实际资源端点。
