# 秘密审计与事件处理最小方案

状态：D-34～D-36 已按合成数据阶段最小方案批准。只实现源开发手册要求，不建设 KMS、WORM、哈希链、独立审计集群或事件工单平台。

## 秘密管理

- 数据库连接、MinIO、JWT、帧 token 和 `mask_map` 密钥通过环境变量注入。
- 仓库只提交 `.env.example`；真实 `.env`、密码、token 和密钥不进入 Git、PR、日志或构建产物。
- 开发和测试使用不同的非生产秘密；JWT、帧 token 和 `mask_map` 使用不同变量。
- 当前不创建生产秘密，也不实现 KMS 或自动轮换系统。

## 审计

- 使用源手册 `audit_logs` 表记录操作者、动作、目标、详情、IP 和时间。
- 帧访问、标注保存、审核、发布、导出审批及账号/资格变更必须写审计。
- 审计只允许 INSERT 和查询，应用与管理员均不得 UPDATE 或 DELETE；审计记录不使用软删除。
- 审计至少保存 3 年。写操作与审计处于同一事务，审计写入失败则事务回滚。
- 不增加 WORM、哈希链、独立存储或专门审计角色系统。

## 事件处理

项目临时负责人负责学生阶段事件处置，采用最小人工流程：

1. 停用异常账号或服务，阻止继续访问；
2. 保留相关审计日志，确认影响范围；
3. 修复原因并更换已泄露的秘密；
4. 验证恢复后记录简短复盘。

当前不建设值班、工单、自动上报或演练管理系统。未来接入真实医学数据时，再补充正式联系人、报告时限和责任单位流程。
