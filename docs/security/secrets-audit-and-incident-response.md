# 密钥、日志审计与安全事件响应方案（WP-S0 草案）

状态：架构基线草案。生产密钥保管方、事件联系人/时限和审计防篡改实现仍待 D-34～D-36 批准。

依据：源开发手册 §2.6、§8.4、§9.3；[需求基线](../医学影像标注平台-需求拆解与实施基线.md) §8、SG-1/SG-6/SG-7、D-34～D-36。

## 1. 密钥与秘密管理

- 真实密码、token、私钥、生产证书、对象存储密钥、数据库连接串和真实 `.env` 不得进入 Git、PR、Issue、Actions 日志或构建产物；仓库仅保留变量名和非敏感示例。
- 开发、测试、生产完全分离；JWT 签名、帧 token、`mask_map`、数据库/对象存储、备份和交付加密按用途分钥，不得复用。
- 运行时由受控秘密存储或平台注入；服务账号只读取本服务所需的秘密，禁止普通管理员页面读取明文。
- 每项秘密登记所有者、用途、环境、算法/长度、创建时间、轮换周期、最近轮换、依赖服务和吊销步骤；值本身不进入登记表。
- 轮换支持重叠验证窗口和明确截止；泄露时立即吊销、替换、失效相关会话/链接并进入事件流程。备份密钥的保管与恢复须职责分离。
- 生产 KMS/密码合规要求及保管责任人待责任单位批准；批准前不创建生产秘密。

## 2. 日志与审计

普通运行日志只记录排障所需的最小字段，禁止记录密码、Bearer/帧 token、密钥、原始 DICOM 标签、原始报告、`mask_map`、UID 原值、请求/响应敏感正文和对象存储 URL。

敏感操作审计至少包含：事件 ID、可信时间、actor/服务身份、会话 ID 哈希、动作、策略 ID、目标类型与伪标识、结果、拒绝阶段、来源批次、必要的前后值摘要、IP/客户端信息和关联请求 ID。至少审计登录/失败/下线、账号和资格变更、授权台账变更、导入/清理、帧访问、标注、审核、发布/下线、导出申请/审批/交付、`mask_map` 访问、密钥轮换、异常锁定/解锁及管理员查询。

- 审计写入只增不删；业务数据库账号和普通管理员无修改/删除权限。
- 审计写入失败时，帧访问、导出、发布、权限变更和映射访问等高风险操作失败关闭并告警。
- 审计至少保留 3 年；精确期限、可信时间、独立存储及哈希链/WORM 等等效完整性机制由 D-36 批准。
- 审计查询和导出本身也审计；安全审计员与业务管理员职责分离。

## 3. 事件响应

触发场景至少包括账号/管理员凭证泄露、签名密钥泄露、原始包误留存、异常批量翻帧、越权访问、导出链接泄露、恶意附件、数据丢失/篡改和审计服务不可用。

1. 发现与分级：告警进入唯一事件编号；值守人按数据级别、影响主体、可利用性和扩散范围初判，不在未调查时宣称无影响。
2. 立即遏制：锁定账号/会话，吊销 token/密钥/链接，隔离服务或对象，暂停导入/导出/发布；不得删除取证材料。
3. 证据保全：保存时间线、配置和审计引用、受影响版本/对象清单及哈希；证据访问最小化并另行审计。
4. 评估与通报：由责任单位、法务/信息安全和数据提供方确认影响、报告/通知对象及时限；开发人员不得自行作法律结论。
5. 清除与恢复：修复根因、轮换凭证、验证备份和隔离边界，按批准的恢复步骤逐项开放。
6. 复盘与演练：记录根因、影响、控制缺口、负责人和期限；账号泄露、密钥泄露、误留存、批量翻帧、导出泄露和审计不可用至少纳入上线前演练。

学生项目阶段由项目发起人作为全项目临时负责人并承担事件负责人职责，但不在仓库保存个人联系方式。24 小时联系人、升级链、监管/数据提供方接口、外部通知时限和演练频率仍待未来真实数据责任单位填写并批准；缺失时 SG-1/SG-7 不得放行真实数据或上线。
