# WP-S0 合成数据阶段决定

核验日期：2026-09-20。源开发手册是开发范围和验收的权威；需求基线只用于工作包追踪和暴露缺口，不得据此扩张产品范围。

## D-30～D-37 决定

| 决策 | 合成数据阶段批准方案 |
| --- | --- |
| D-30 保留与删除 | 采用手册现有期限：审计至少 3 年、PostgreSQL 备份 30 份、帧缓存 30 分钟、业务表软删除；不建删除编排系统 |
| D-31 来源记录 | `cases.source=synthetic`；不新增授权台账表或审批系统，真实数据接入前再设计 |
| D-32 浏览器 token | 8 小时 JWT 仅存浏览器内存，无 refresh token；每请求检查账号状态，不建黑名单或会话平台 |
| D-33 分类与等保 | 当前只记录“仅合成数据”；不开发分级系统、不宣称等保等级 |
| D-34 密钥管理 | 使用环境变量和 GitHub Secrets，按 JWT、帧 token、`mask_map` 分变量；不建 KMS/自动轮换系统 |
| D-35 事件响应 | 项目临时负责人按停用、留证、修复、复盘四步人工处理；不建事件平台 |
| D-36 审计防篡改 | PostgreSQL `audit_logs` 只允许 INSERT/查询，禁止 UPDATE/DELETE，至少保留 3 年；不建 WORM/哈希链 |
| D-37 DICOM 去标识化 | Basic Application Level Confidentiality Profile + Clean Pixel Data，按手册字段、首帧 OCR 和人工确认实现；不提前启用其他 Options |

以上方案已由项目临时负责人批准，只允许推动合成数据开发。真实医学数据接入前必须重新评审 D-30、D-31、D-33～D-37 的实际要求。

## 源手册验收基线

- 权限：登录、账号状态、角色/资格、任务分派和资源顺序校验；覆盖越权与停用立即失效。
- 脱敏：DICOM 身份字段、首帧 OCR、报告/临床文本人名遮蔽和人工确认。
- 防下载：无原始影像接口；5 分钟帧 token、水印、限流、锁定和审计。
- 基础设施：只有 nginx 对外，PostgreSQL、Orthanc、MinIO、Redis 和 Elasticsearch 均仅内网访问。
- 审计与导出：审计只增不删且至少 3 年；导出申请人与审批人为不同管理员。
